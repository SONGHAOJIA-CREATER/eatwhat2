# 写法示范：编辑一条长期偏好

更新：2026-10-18。对应 D-02 的教学示范，用来说明需求应写多细；正式主稿仍是 [D 模块](../模块/D-反馈与偏好.md)。下面控件、提示和等待状态属于示范提案，D 可参考后提出自己的产品方案，由 A 汇总采用内容与未定项，不要求先经技术评审。这里没有记录实际用户试用或实现验收结果。

## 1. 场景、目标和范围

用户在个人页看到“不推荐面食”，想改成“不推荐家常饭”。目标是修改一条已经存在的长期偏好，让后续推荐使用新记录。

本功能覆盖进入编辑、修改、取消、保存结果及返回首页后的影响。其他偏好的创建、聊天结束提取、账号与存储实现分别由相关需求说明。

依据：[PRD](../../PRD.md)第 3.2 节、R-08、R-09 和第 7 节。长期记录可纠正，切页保留当前选餐信息；偏好变化后需让后续推荐使用有效记录。

## 2. 入口与输入输出

入口：我的 → 长期偏好与限制 → 某条记录的“编辑”。前提：这条记录已存在，且属于当前使用者。身份实现按 Q-10 另行确认。

| 信息 | 含义及来源 | 本功能怎样使用 |
| --- | --- | --- |
| 记录身份 | 用于区分具体哪一条，由保存能力提供 | 修改正确的记录，不根据显示文案猜记录 |
| 原内容 | 已有类别“面食”及“不推荐”的含义 | 列表和编辑初始值使用原内容 |
| 范围 | 已有记录为长期 | 清楚显示，避免误解成只影响今天 |
| 来源 | 这条记录为什么形成；有依据才展示 | 显示已有来源；主动修改后的来源表达与 D/E 对齐 |
| 用户的新内容 | 本例改为“家常饭” | 仅作为待保存内容，成功后才当作有效记录 |
| 当前选餐状态 | 当前条件、聊天、未发送文字 | 切页保留；成功后通知推荐需要更新 |

下游交接：D 向 C 提供已成功生效的偏好变化；C 收起按旧记录生成的可选结果，并在重新获取后使用新记录；E 统一提示和返回表现。

## 3. 操作和状态表

| 画面编号 | 用户操作或状态 | 产品响应 | 需要保留什么 |
| --- | --- | --- | --- |
| D-S01 列表 | 查看已有记录 | 显示“不推荐面食”、长期范围和已有来源，提供编辑入口 | 其他偏好保持原状 |
| D-S02 编辑 | 点击编辑 | 展示原类别，说明本次改的是长期记录，提供保存和取消 | 原记录仍有效，新选择为待保存内容 |
| D-S02 编辑 | 选择“家常饭” | 更新编辑区的待保存内容 | 原记录和当前选餐信息 |
| D-S01 列表 | 点击取消 | 退出编辑，列表仍显示“不推荐面食” | 原记录不变 |
| D-S03 保存中 | 点击保存 | 提示“正在保存”，暂时避免重复保存；等待结果 | 本次编辑内容与原记录 |
| D-S04 保存成功 | 收到成功结果 | 列表显示“不推荐家常饭”，给出保存成功提示 | 其他偏好及当前选餐信息 |
| D-S05 保存失败 | 收到失败结果 | 明确提示“没有保存成功”，保留修改内容，提供重试和取消 | 原记录继续有效，本次编辑内容仍在 |
| C-S01 需要更新 | 成功后回到首页 | 保留聊天和条件，提示重新获取推荐；旧卡片不继续作为当前可选结果 | 原话、条件、未发送文字 |
| C-S02 新推荐 | 用户重新获取 | 使用新偏好，停止使用原偏好；当前其他限制继续生效 | 其他有效条件与偏好 |

文案示例：“偏好已更新，回首页后重新获取推荐。”这些是供评审的具体文案，不是已定稿文案。

## 4. 怎么画草图

用现有个人页截图标出 D-S01、D-S02；在 D-S02 旁标注保存中和保存失败的变化。再用首页截图说明 C-S01。不需要为五个状态各画一张完整高保真页面。

当前[原型](../原型/index.html)的“偏好纠错”路径可以演示编辑、取消、返回和重新获取；没有真实保存请求，D-S03、D-S05 需另补草图，不能当作原型已验证。

## 5. 行为例子：给定／当／应当

| 编号 | 给定 | 当用户或系统 | 应当观察到 |
| --- | --- | --- | --- |
| D-EX01 正常保存 | 已有“不推荐面食” | 改为家常饭并成功保存 | 列表显示新内容，原限制被替换，其他偏好不变 |
| D-EX02 取消 | 编辑中选了家常饭，尚未保存 | 点击取消 | 列表仍显示“不推荐面食” |
| D-EX03 保存失败 | 编辑内容为家常饭 | 保存请求失败 | 明示失败、保留修改供重试；原记录仍有效 |
| D-EX04 返回首页 | 新偏好已成功保存，首页原有聊天和草稿 | 返回首页 | 聊天、条件、草稿保留；旧卡片退出当前可选结果，提示更新 |
| D-EX05 使用新记录 | 原本只有一条排除面食的限制，已经改为排除家常饭 | 再次获取推荐 | 按新限制处理；没有其他限制时，不继续因为旧记录排除面食 |

这些是需求预期，不是已执行结果。首轮可以先写前三例和跨页影响，后续补关键分支；不要求产品成员运行真实保存接口。

## 6. 还要共同判断什么

- D/E：编辑对象采用什么控件，来源怎样表达，保存提示放哪里。
- D/C：哪些变更影响当前结果，更新入口和旧结果退出的时机怎样一致。
- 单列给开发团队：记录身份、失败结果的提供方式与存储实现；D 写清预期归属和失败时产品行为，不负责确认技术方案。
- 新取舍由主责提出建议；跨模块结论由 A 汇入[决策记录](../决策记录.md)，正式行为更新回 D/C 模块。
