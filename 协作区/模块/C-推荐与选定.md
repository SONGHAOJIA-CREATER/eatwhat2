本稿是 C 的首轮设计底稿。人员和进度见 [任务看板](../任务看板.md)，对应 T-C01、T-C02。接收 B 的已确认条件，反馈对象交给 D。

当前接续 [PRD v0.4 第 3 至 8 节](../../PRD.md)，按地图、推荐卡片与对话辅助的工作方案画粗稿。下文是既有起草参考，地图联动和详细状态由 C 接续完善。

## C 第一次接任务，按这个顺序做

先读[新成员引导](../新成员开始这里.md)，在原型查看三家推荐、点位、换一组和就这家，再读 PRD 的 R-03、R-04、R-07、R-10。你负责让用户看懂候选之间的区别，并能明确完成选择。

**独立起点：** 直接用 PRD 第 7.1 节的已齐全条件和样例餐厅设计，不等待 B 交稿、D 的最终反馈控件或真实地图接入。未知字段和异常用明确标注的设计样例表达；交自己的需求、草图、案例和未定问题，真实字段可得性另列给开发团队，不作为提交条件。

### 需要你作出的判断

1. 主推荐和备选各显示什么，哪些内容始终可见，哪些展开后操作？
2. 三种角色的理由怎样不同？哪些事实来自数据，哪些只是解释，缺失时怎样提示？
3. 点位与卡片怎样让用户对应起来？查看与选定怎样区分？
4. 换推荐出现重复或没有更多候选时，怎样解释并继续？
5. 选定后显示什么，怎样提供位置帮助；后续反馈入口与 D 怎样衔接？

角色数量、字段真实性和不凑候选按已有规则执行。写清期望显示的信息、来源要求与未知时的表现；算法、地图供应商、真实数据可得性和接入代价由开发团队另行确认。

### 提交与配合

在本稿补字段表、操作表、草图链接和至少 3 条案例，首轮覆盖正常推荐、候选不足、查看点位与明确选定的区别。后续说明未知字段、无匹配与失败分支。未定问题附建议，自查后即可提交 A。

产品运行时接收 B 的已确认条件，条件不齐交回 B，不自行猜测；设计时直接用共同样例。向 D 交“本次选择、具体餐厅、类别、反馈内容和明确对象”，例如“家常饭 A → 家常饭类别 → 今天不吃这类”。向 E 交各状态和必须保留的信息；向 A 提交范围和地图取舍建议，真实字段疑问列入开发交接清单。

## C-01 三种角色的推荐卡片

依据 [PRD 第 6 节 R-03、R-04](../../PRD.md)，默认展示最稳妥、轻探索、低风险兜底三种角色，每张卡片有一句主理由和两个有依据的标签。排序由程序负责，理由解释排序结果；既有细则见[参考文档第 6、12、14 节](../既有业务规则与调研依据.md)。

| 字段 | 来源要求 | 缺失时的设计要求 |
| --- | --- | --- |
| 餐厅名称及身份 | 真实候选，稳定标识由技术提供 | 不凭模型补造候选 |
| 地点与距离 | 地图候选或经确认的距离计算 | 标未知；不换算成未经验证的步行时间 |
| 参考价格 | 可用的来源字段 | 标未知；预算处理按 Q-05 |
| 推荐角色与理由 | 排序输出和可追溯依据 | 不能声称没有证据的“不排队”“不油腻” |
| 历史反馈标签 | 当前用户有效反馈 | 无记录时不显示个性化断言 |

候选不足三家时返回实际数量；无匹配和接口失败分别设计。上述细节为工作稿，与 B/E 的衔接疑问写清假设和影响，由 A 汇总；真实字段另交开发团队核对。

## C-02 换推荐与明确选定

| 操作 | 设计草案 | 需要完成的交接 |
| --- | --- | --- |
| 换一组 | 保留当前条件和有效限制，重新给出符合条件的选项 | 重复店、无更多候选的行为需 C 细化 |
| 修改条件 | 返回 B 的条件修改，保留其他已知值 | 明确原推荐是否失效及加载期间的显示 |
| 就这家 | 给用户明确的选定确认 | 餐厅和本次决策身份交 D，统计按 Q-04 |
| 查看地图 | 提供位置辅助，不直接代替“选定”动作 | 按 Q-02 提交展示与操作建议，接入方式另交开发团队 |

## 行为例子（需求自查用）

- C-AC01：三张卡片的角色和理由可对应到输入和来源。
- C-AC02：只有两家合格候选时不编造第三家。
- C-AC03：换推荐不取消已生效的当次限制和长期明确限制。
- C-AC04：价格未知时不展示为已确认符合严格预算。
- C-AC05：打开地图与明确选定可区分，选定不自动等于用餐满意。

## C 认领后的具体动作

补三卡片、两卡片、无匹配、价格未知、选定结果的草图和操作说明；补换推荐的重复规则。Q-02、Q-05、Q-07 未有结论时写自己的建议及开发疑问，自查后提交；有结论再同步。可参照 [当前固定原型](../原型/index.html)，其价格和距离只用于展示。
