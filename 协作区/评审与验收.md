# EatWhat 产品交付自查与试用参考

更新于 2026-10-18。本文件只帮助产品成员检查需求和画面，并提供可选的试用方法。保留原文件名以兼容已有链接；技术方案、开发排期和实现验收由开发团队另行安排。

## 交稿前自己检查什么

每项任务交四样：

1. **需求说明：** 场景、入口、输入、用户操作、产品响应、关键分支及模块影响。
2. **草图或设计稿：** 链接与状态编号能对应文字；截图批注、纸笔或 PPT 都可以。
3. **至少 3 条行为例子：** 说明“给定什么、做什么、应当发生什么”，覆盖正常、缺失或失败、取消或返回。
4. **待定问题：** 写自己的建议、暂用假设和影响；没有待定项也注明“暂无”。产品取舍交 A，技术疑问另列给开发团队。

自己按案例走一遍，确认别人能看懂每一步的预期变化，就可以在看板标“已提交”。不要求指定评审人、评审会议、真实用户试用或开发团队确认。A 分批整合采用内容与未定项，随后标“已汇总”。

## 可选的原型试用任务

有余力时可使用下面的任务，各自在方便的时间观察一名参与者，或异步阅读已有记录，无需全员同场。E 分析交互与视觉，B/C/D 关注各自业务；实际发现写入下方记录，主责在自己的工作时段处理。未开展试用时记录留空，不影响产品稿提交。

使用 [当前固定示例原型](./原型/index.html)。先让参与者自己尝试，再追问原因；记录操作与原话，不替用户解释每一步。

| 任务 | 给参与者的任务描述 | 观察什么 |
| --- | --- | --- |
| U-01 | 从示例需求开始，选定一顿 30 元以内的午饭 | 是否知道怎么开始；是否理解地点补问；能否比较三种推荐 |
| U-02 | 今天不想吃其中一类，换一个合适的选择 | 是否找到反馈；是否理解只在本次生效；能否继续选定 |
| U-03 | 评审人先载入“偏好纠错”场景；请参与者把“不推荐面食”改成其他类别，返回查看影响，再删除该记录 | 是否看懂来源与长期范围；是否理解需要更新推荐；是否知道取消与删除后的含义 |

原型中的反馈和已有偏好是示例，不当作真实用餐满意度或用户记录。自由文本理解、真实地理位置、完整八标签、长期反馈保存及接口失败恢复仍需模块负责人补充；不能因为固定脚本可点击就判定整个模块已完成。

## 跨模块行为例子

这些案例用于检查产品说明是否讲清预期，也可随产品资料交给开发团队参考，不要求产品成员执行真实接口或实现测试。各模块可补充案例，关键取舍以 PRD 和决策记录为准。

| 编号 | 给定情况 | 预期行为 | 涉及方向 |
| --- | --- | --- | --- |
| AC-01 | 用户没有提供地点，也没有有效位置 | 补充位置后才能推荐附近餐厅 | A/B |
| AC-02 | 原话已经包含人数和预算 | 不重复询问已确定的信息 | B |
| AC-03 | 用户使用此前确认的预算默认值 | 展示所用默认值，并允许修改 | B/C |
| AC-04 | 合格候选只有两家 | 返回实际候选，不补造第三家或放宽明确限制 | C |
| AC-05 | 用户提交“今天不想吃这个” | 本次生效，不因此产生长期限制 | C/D |
| AC-06 | 用户明确提交“这类以后别推荐” | 按确认规则形成长期限制，后续推荐使用该限制 | C/D |
| AC-07 | 用户删除一条有效偏好 | 后续推荐不再使用该条偏好；其他有效偏好保持各自规则 | D/C |
| AC-08 | 用户点击“就这家”，尚未提供用餐后反馈 | 选定与满意分别记录，后续反馈为未知 | C/E，统计口径待 Q-04 确认 |
| AC-09 | 地图或模型调用失败 | 明确显示失败，不伪装成没有餐厅；保留可继续操作的输入 | B/C/E 说明产品表现 |
| AC-10 | 某餐厅价格缺失 | 标为未知，不直接声称符合严格预算；具体处理按 Q-05 | C |
| AC-11 | 两个不同访问者查看偏好 | 只能看到各自的记录 | D 说明记录归属与使用边界，身份实现另交开发团队 |

## A 汇总后怎样交接产品资料

各模块独立提交后，A 分批汇总：

- 将采用的产品行为汇入 PRD，或精确引用模块需求及画面编号。
- 统一跨模块术语、操作与返回关系；已知冲突保留问题、建议和影响。
- 未定的产品取舍与开发团队需回答的技术疑问分开列明，不伪装成已解决。
- 汇总 PRD、模块说明、原型／视觉稿及行为例子的入口，供开发团队另行安排实现。

```text
产品交接说明
产品版本与本轮范围：
PRD 及模块需求链接：
原型／视觉稿链接与画面编号：
行为例子：
已采用的方案：
未定产品问题及建议：
交给开发团队的技术疑问：
暂不包含的部分：
```

本组工作到产品资料提交与汇总为止。开发团队接收后自行安排技术方案、估算、开发与实现验收；其确认和进度不作为产品任务完成条件。
