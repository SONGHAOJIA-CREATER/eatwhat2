# EatWhat 原型入口

更新于 2026-10-18。打开 [index.html](./index.html)，或在电脑浏览器中双击此文件。当前是 A 提供的手机网页灰度框架稿，视觉方案待设计专业同学认领。

## 三条可点击路径

| 路径 | 怎么体验 | 重点看什么 |
| --- | --- | --- |
| 首次选餐 | 填入示例 → 帮我选一顿 → 补学校东门 → 应用条件 → 比较或选定 | 已知人数和预算预填；缺地点不能推荐；首页和我的可往返 |
| 当次反馈 | 在评审说明选“当次反馈” → 点“今天不吃这类” → 换一组 → 开始新一餐 | 排除对象是当前卡片类别；不写入长期偏好；新一餐清除当次限制 |
| 偏好纠错 | 在评审说明选“偏好纠错” → 编辑或删除已有记录 → 回首页 → 按新条件更新 | 对象、长期范围和来源可见；取消保留原值；更新前旧卡片收起；新结果停止使用旧记录 |

评审说明在电脑右侧、手机布局下方。这里切换路径会重置所有示例；产品内“开始新一餐”保留长期偏好和默认值，重新补地点。偏好纠错使用明确预置的记录，不模拟聊天反馈自动变成长期记录。

## 这版覆盖什么

- 首页／我的固定导航，切页保留当前需求、聊天记录和未发送文字。
- 示意地图与当前候选对应；点位展开卡片，查看位置回到地图。查看和选定是不同操作。
- 主推荐默认展开，另外两家保留名称、参考价格、距离和理由，展开后可操作。地图可收起。
- 三种角色、候选不足和无匹配；换推荐保留条件，不足不凑数、不自动放宽预算。
- 条件修改、默认预算、当次排除；条件变更提示重新获取推荐。
- 个人页的偏好空状态、来源与范围、编辑取消、删除确认、返回后更新推荐。

这版将既有公开项目中地图、卡片与对话围绕同一批结果组织的做法用于手机布局，延续 [PRD 第 11 节](../../PRD.md)的参考依据。复用交互关系，代码保持原有无框架、无外部依赖的形式。

## 样例与未覆盖范围

餐厅、价格、距离、预算单位、学校东门均为样例；示意地图没有真实地理含义。只在当前页面内保留状态，关闭或刷新重置。没有连接真实地图、模型、账号或存储。

输入只支持“一个人，30 元以内，今天不想吃面。”、“一个人，30 元以内。”和“附近有什么好吃的？”，也可直接填写条件。对话调整支持“预算改成20元”、“预算改成30元”和“今天不想吃面”。不支持的原话会给出提示。

模块负责人继续说明定位、任意语句理解、完整八标签、生效提示、保存失败、记录归属和外部导航的用户可见行为；实际能力由开发团队另行实现。当前不提供伪造的加载等待或接口成功。桌面浏览器中的手机宽度检查不等于真实手机操作或推荐效果验收。

## 接下来怎样分工

按 [任务看板](../任务看板.md)认领；原型是共同起点，不代表 B/C/D/E 任务已完成。

- B：补引导、缺失信息、定位失败及手动地点、条件与默认值的细节。
- C：补地图和卡片的详细状态、价格未知、无更多候选及外部导航。
- D：补八标签、长期保存时机、保存失败和记录归属；核对个人页纠错。
- E（设计专业同学）：补公共状态、手机键盘与触摸表现；完成 [E-03](../模块/E-交互与用户验证.md)的配色、字体、公共控件和两页关键画面。设计同学包含在五名产品成员内，姓名在看板登记。
- A 提供共同场景和自查说明，按收到的产品稿分批汇总。互评与试用可选；有实际记录时，E 分析交互与视觉问题，各模块处理自己的问题。新同学先读[入门引导](../新成员开始这里.md)，直接使用 PRD 的共同样例独立开工。

## 修改源与导出

`eatwhat-flow.fragment.html` 是唯一界面源，`index.html` 是其完整浏览器导出。色值集中在源文件顶部的 `--ew-*` 变量。可以交设计稿或规范，不需要会改代码；共享原型由 A/E 协调合入。

导出脚本只用 Node.js 标准库，不需要安装依赖。在本目录运行：

```text
node export.cjs
```

导出后核对三条路径和本次变更。源与导出必须保持一致。此前聊天副本保留作背景，当前以本目录为准。
